# Implementation Plan: Waiver Drop ESPN Status Display

**Branch**: `006-waiver-drop-espn-status` | **Date**: 2026-06-08 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/006-waiver-drop-espn-status/spec.md`

## Summary

Surface the ESPN injury status (IR, DTD, 10-IL, etc.) for each dropped player in the waiver drop review. The `injury_status` field is already fetched from ESPN and stored on `PlayerRecord` — it simply needs to be normalized to a short display label and included in the service output, the CLI print, and the frontend card. Three additive touch points; no existing behaviour changes.

## Implementation Phases

### Phase 1 — Service layer

1. Add `_ESPN_STATUS_LABELS` dict and `_normalize_espn_status()` helper to `services/waivers_service.py`
2. Add `"espn_status": _normalize_espn_status(player.injury_status)` return in `_serialize_hitter_row()`
3. Add `"espn_status": _normalize_espn_status(player.injury_status)` return in `_serialize_pitcher_row()`
4. In `get_recent_drops_waiver_review()`, add `"espn_status": row["espn_status"]` to the `serialized` dict (applies to both hitter and pitcher branches)

### Phase 2 — CLI output

5. In `run_recent_drops_waiver_review.py`, read `row.get("espn_status")` and append `[STATUS]` to the player header print line when non-null

### Phase 3 — Frontend

6. Add `espn_status: string | null` to the `DropRow` interface in `RecentDrops.tsx`
7. Render a red-tinted badge `[STATUS]` next to the player name when `espn_status` is non-null
