# Implementation Plan: Lineup & Bench Card

**Branch**: `011-lineup-bench-card` | **Date**: 2026-06-24 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/011-lineup-bench-card/spec.md`

## Summary

Add a `LineupCard` React component to the dashboard that displays the user's fantasy starting roster and bench in two sections, showing each player's fantasy slot and whether they are confirmed in their real-life batting order. The backend serves a new `GET /api/my-roster` endpoint that combines ESPN roster data (player slot assignment) with the existing MLB Stats lineup-status lookup from feature 010.

## Technical Context

**Language/Version**: Python 3.11 (backend) · TypeScript / React 18 (frontend)

**Primary Dependencies**: FastAPI, espn-api, mlb-statsapi (all existing); React + Tailwind CSS (existing)

**Storage**: No new storage. Response cache TTL 120 s via existing `response_cache`.

**Testing**: pytest (backend) · no frontend unit tests (existing project convention)

**Target Platform**: Linux server (Docker) + Vite dev server on localhost:5173

**Project Type**: Web service + React SPA (existing)

**Performance Goals**: Card loads within 3 s — same bar as other dashboard cards

**Constraints**: No new dependencies. No new abstractions. Must fit the existing two-column dashboard grid.

**Scale/Scope**: One team's roster (~25 players); per-player MLB status lookups are parallelized.

## Implementation Notes (for tasks)

### Backend: `services/roster_card_service.py`

Mirrors `optimizer_service.py`'s shape. Key steps:
1. `build_context(config)` → `get_team()` → `get_roster_players()`
2. For each player, read `lineup_slot = str(getattr(player.espn_raw, "lineupSlot", "") or "").upper()`
3. `_BENCH_SLOTS = {"BE", "IL", "IL10", "IL15", "IL60", "NA"}` → split into `starters` and `bench` lists
4. For hitters only: `ThreadPoolExecutor` to call `get_player_lineup_status(name)` in parallel (same pattern as `mlb_stats.py` pitcher stats fetch)
5. Return serialized dict matching the API contract in `contracts/api-my-roster.md`

### Backend: `app/routes/my_roster.py`

Mirrors `app/routes/optimizer.py` exactly:
- `router = APIRouter()`
- `@router.get("/my-roster")`
- `response_cache.get / response_cache.set` with 120 s TTL
- Delegates entirely to `roster_card_service.get_roster_card()`

### Backend: `app/main.py`

Register the new router — same two-line pattern used for every other route:
```python
from app.routes.my_roster import router as my_roster_router
app.include_router(my_roster_router, prefix="/api")
```

### Frontend: `api.ts`

Add one line to the `api` object:
```ts
myRoster: () => apiFetch('/api/my-roster'),
```

### Frontend: `LineupCard.tsx`

Structure mirrors `RecentDrops.tsx`:
- `useEffect` fetches `api.myRoster()`, stores `{ starters, bench }` in state
- Wraps in `<Card title="My Lineup" loading={loading} error={error}>`
- **Starters section**: `<div>` with a `"STARTERS"` label, then a `divide-y divide-gray-800` list
- **Divider**: `<div className="border-t border-gray-700 my-1" />` + `"BENCH"` label
- **Bench section**: same list structure
- Each **player row**: identical markup to `RecentDrops.tsx` rows —
  - Left column: player name (white, `text-sm font-medium`) + optional injury badge (reuse `injuryColor` / `injuryLabel`) + `text-xs text-gray-400` for MLb team + slot
  - Right column: lineup status badge — green `"▶ In Lineup"` / yellow `"? Not Posted"` / gray `"— No Game"` / red `"✕ Out"` based on `lineup_status` value

### Frontend: `App.tsx`

Add `<LineupCard />` to the dashboard grid — one import, one JSX element in the existing `<div className="grid …">`. Place it after `<WeeklyScores />` or as the first card (user's choice at implementation time).
